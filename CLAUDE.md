## Project context

Suositusautomaatio + website for the Finnish HS podcast "Uutisraportti". The pipeline pulls new episodes from the RSS feed, transcribes the intro + last 10 minutes (the recommendations segment) with Deepgram, then has Claude extract structured cultural/consumer recommendations into `suositukset.json`. That JSON powers the static site at uutisrapsa.fi (Netlify, publishes this repo's root from GitHub `main`).

**Everything lives in this one repo since 16.9.2026** (github.com/albrto/**uutisrapsa** (renamed 16.9.2026 from uutisraportti-suosittelee; GitHub redirects the old name), working copy `/Users/antero/Koodi/uutisrapsa`):

- **Repo root** — the published site (`index.html`, `app.js`, `style.css`, `suositukset.json`), `admin/` UI, `transkriptit/` (shared speaker-labeled transcript cache, robots-disallowed), `scripts/` (the copies GitHub Actions runs), `julkaise.sh`, workflows.
- **`pipeline/`** — the local toolbox (previously a separate iCloud folder `…/com~apple~CloudDocs/Koodi/Uutisrapsa.fi`, and before that Google Antigravity's scratch dir where the project started). Scripts are committed; **secrets and local data copies are gitignored** (`.env`, `venv/`, `suositukset.json` + backups, `historia_json.txt` + backups, `korjaukset.json`, `ohitukset.json`, `korjausehdotukset.json`, `supla_audio_urlit.json`, `ajon_tulos.json`, `validointidata/epailyttavat.*`, `screenshotit/`). Gitignored files never reach GitHub or Netlify — but they also have **no backup** (the iCloud safety net is gone), so treat `pipeline/korjausehdotukset.json` and the local data copies with care.

Netlify serves everything committed at the repo root, so committed pipeline files are public (like `scripts/` always was); `robots.txt` disallows `/admin/`, `/transkriptit/`, `/pipeline/` and `/scripts/` from search engines.

All code, identifiers, comments, prompts, and logs are in Finnish. Match that when editing — don't translate variable names or rewrite prompts in English.

## Front-end architecture (since 2.10.2026, built on `dev`, live 19.10.2026)

The public site is a dependency-free single-page app (index.html + app.js + style.css, no build step). One page serves every view; `netlify.toml` `[[redirects]]` (status 200 rewrites) send these paths to `index.html`, and `app.js` routes by `location`:

| URL | View |
|---|---|
| `/` | hero + all recs (newest episode highlighted as "Uusin jakso") |
| `/suosittelija/<slug>` | recommender page: profile (avatar, counts, category split bar) + their recs. Reached by clicking a name (cards, rec view, Tilastot); its "← Takaisin" link is a real history step back to wherever the user came from (`history.state.edellinen`, set by `siirry`), or "← Kaikki suosittelijat" on a direct visit |
| `/suosikit` | favorites (localStorage key `suosikit`, list of rec ids) |
| `/yllata` | "Yllätä minut": random rec on a one-reel slot machine with a pull lever and a genre filter |
| `/tilastot`, `/tilastot/ilmiot`, `/suosittelijat` | Tilastot section with three tabs: Top-listat, Ilmiöt (charts; named "Kuviot" until the user renamed it 2.10.2026 — `/tilastot/kuviot` still redirects), Suosittelijat (directory) |
| `/suositus/<teos-slug>-<id>` | a rec's own view, a `<dialog>` over the view it was opened from (`history.state.paluu`) |

Filters live in the query string (`q`, `kategoria`, `suosittelija` = recommender slug, `vuosi`, `teos` = repeat-group slug, `toistuvat=1`, `jarjestys=vanhin`), so every view is a shareable link. View changes `pushState`; filter/search changes `replaceState`. Every dialog (rec view, feedback, about) gets its own history entry with a unique `avain`, so the phone back gesture closes it and stale entries (Forward button, reload) never get confused with a newly opened dialog; filter changes made inside the filter panel are carried to the base entry on close (`siirtoOsoite`, only when Back lands exactly on that entry). A directly loaded `/suositus/…` link gets the home view pushed underneath it, so Back closes the dialog instead of leaving the site; an unknown `/suosittelija/<slug>` redirects to `/suosittelijat` with a toast. Feedback/about dialogs work even if `suositukset.json` fails to load (`setupPerustoiminnot`). Because sub-paths exist, **all asset paths in index.html/app.js are absolute** (`/style.css`, `/app.js`, `/suositukset.json`, `/muutokset.html`) — a relative path would hit the rewrite and get index.html back.

## ⚠️ Production runs in GitHub Actions, not locally

The live pipeline is `.github/workflows/automaatio.yml`, running Thursdays 16:00 UTC and on pushes to **main** touching `admin/korjaukset.json` or `ohitukset.json` (branch filter added 15.9.2026 so the `dev` branch — Netlify branch deploy at `dev--uutisrapsa.netlify.app`, noindex'd via a `[context.branch-deploy]` build command in `netlify.toml` — can't trigger production runs). The job has `timeout-minutes: 45` (added 15.9.2026 after the 3.9.2026 run hung in `apt-get` for GitHub's full 6 h limit and silently skipped the week — the 10.9. run then caught up both episodes). It uses the pipeline-script copies in `scripts/` and commits results to GitHub → Netlify publishes. **Hardening (1.10.2026):** the ffmpeg install step (`apt-get`) hung again (as on 3.9.) — it now has `timeout-minutes: 12`, a `timeout` + `Acquire::*::Timeout` on every apt command, tries `install` before the slow `update`, and retries 3× — and since 2.10.2026 the step is `continue-on-error: true` (apt failed for 12+ min again; corrections and publishing don't need ffmpeg, only cutting a NEW episode does, and step 2 then fails and alerts). The commit step retries the push up to 3× with `git pull --rebase origin main` in between, because a manual push during the run starts Muutosloki, which isn't serialized with a run that is already going and moves main. **Never start a human commit message with `Automaatio:`** — `generoi_muutosloki.py` stops at the first such commit, so everything older is left out of the public changelog (happened once 1.10.2026).

The old local launchd job (`com.uutisrapsa.automaatio.plist`) was **removed entirely 16.9.2026** — it had been permanently failing since ~April 2026 because macOS TCC blocked launchd from executing scripts inside the then-iCloud path ("Operation not permitted"). Last full manual sync: 6.8.2026 (timestamped backups kept alongside); `synkronoi_pilvi_tiedostot.py` merged admin corrections up to 16.9.2026. The repo-root `suositukset.json` (maintained by Actions) is the authority — re-sync `pipeline/suositukset.json` from it before any local publish.

### The correction loop (admin UI → git → pipeline → site)

Corrections and skip-flags are entered through the admin UI at `/admin/` (used mostly on a computer; working nicely on an iPad from the couch is an original wish that still matters for UI work). They reach the local tooling via:

1. `git pull` (done by `aja_automaatio.sh` / `paivita_korjaukset.sh`).
2. `pipeline/synkronoi_pilvi_tiedostot.py` merges `admin/ohitukset.json` and `admin/korjaukset.json` into `pipeline/ohitukset.json` and `pipeline/korjaukset.json` (dedup key: `(jakso_id, r_idx)`, plus `tyyppi` for korjaukset).
3. `scripts/sovella_korjaukset.py` (run by `paivita_korjaukset.sh` with `UUTISRAPSA_DATAKANSIO=pipeline/`) applies corrections in-place to `pipeline/suositukset.json` (with timestamped backup), then `paivita_korjaukset.sh` regenerates validation data and runs `../julkaise.sh` (copies `pipeline/suositukset.json` → repo root, commits, pushes → Netlify).

`ohitukset.json` = permanent "this suspicious recommender is actually correct, stop flagging it" list. `korjaukset.json` = pending corrections to apply once.

**Correction schemas:** `admin/korjaukset.json` uses the **full-record schema** `{jakso_id, r_idx, teos, uusi_data: {teos, suosittelija, kuvaus, paakategoria, kategoriat}}` (can correct any field, `uusi_data` applied wholesale); the old rename-only schema `{jakso_id, r_idx, vanha_suosittelija, uusi_suosittelija}` is still accepted (with a `vanha_suosittelija` mismatch guard). **Additions** (admin UI "＋ Lisää suositus", in the Kaikki/Korjatut views; added 27.9.2026 after the 3.3.2022 episode turned out to be missing two recs) use `{tyyppi: "lisays", jakso_id, r_idx, teos, uusi_data: {teos, suosittelija, kuvaus, paakategoria, kategoriat, google_linkki, lisatieto_linkki}}` and always **append** to the end of the episode, so existing `r_idx` references never shift. `r_idx` is the slot the rec will get, assigned server-side by `netlify/functions/tallenna.js` (= episode length in main's `suositukset.json`, or after any still-pending additions — the deployed site can lag). Because the whole `korjaukset.json` is replayed every run, `sovella_korjaukset.py` skips an addition whose slot is already filled (idempotent) and refuses one whose slot is past the end; a later edit of an added rec is an ordinary correction on that `r_idx`. The admin UI shows saved-but-unapplied additions as recs (badge "Lisätty"). `synkronoi_pilvi_tiedostot.py` dedups by `(jakso_id, r_idx, tyyppi)` so an addition and a later edit of the same slot both survive. **Deletions** ("poistotoiminto", 2.10.2026) are a hide flag, never a list removal (that would shift every later `r_idx`): `{tyyppi: "poisto", jakso_id, jakso_otsikko, paivamaara, r_idx, teos}` makes `sovella_korjaukset.py` set `piilotettu: true` on the rec (teos guard: skipped with an error if the slot holds a different, not-yet-hidden work; idempotent on replay). Undo = a later ordinary correction with `uusi_data: {piilotettu: false}` (entries replay in order, so the last one wins). Hidden recs stay in `suositukset.json`; `app.js` skips them when flattening, `scripts/generoi_validointidata.py` never flags them (and passes `piilotettu` to the admin), `pipeline/validoi_suosittelijat.py` skips them. Admin UI: "Piilota sivulta" / "Palauta sivulle" buttons on every rec without unsaved local edits (also on previously corrected ones), dashed dimmed card + badge "Piilotettu sivulta"/"Piilotetaan"; the state of saved-but-unapplied entries comes from the last poisto/`piilotettu` entry for that slot (`getCorr`). `tallenna.js` passes poisto entries through unchanged; the reorder function remaps their `r_idx` like any other entry. (`tallenna.js`/`ohita.js` still pointed at the pre-rename repo name until 27.9.2026 — fixed to `albrto/uutisrapsa`.) Since the 16.9.2026 unification the single `scripts/sovella_korjaukset.py` handles **both schemas in both contexts** — the old local-scripts-skip-new-schema divergence is gone. **Note the consequence:** new-schema entries merged into `pipeline/korjaukset.json` by `synkronoi_pilvi_tiedostot.py` are no longer inert locally; running `paivita_korjaukset.sh` re-applies them to the local copy (idempotent — they're already applied in production data, which local copies are synced from). New corrections should be pushed as `admin/korjaukset.json` on main, which triggers the production workflow.

**Direct edits of the root `suositukset.json`** are also fine for one-off fixes done from Claude Code (e.g. 27.9.2026: the 30.3. and 6.4.2023 episodes — Succession-sessio podcast re-attributed, wrong "(Yle)" label, two swapped recommenders and two missing recs added): `git pull` first, edit only the affected episode, append new recs to the episode's end (never reorder), commit + push → Netlify publishes; Actions keeps the edits because it works on the committed root file. ### AI-assisted re-attribution (pipeline/korjaa_suosittelijat.py)

Re-processes episodes flagged in `pipeline/validointidata/epailyttavat.json`: uses the `transkriptit/` cache (or re-downloads + re-transcribes with diarization), then asks Claude to re-attribute **only** the flagged recommendations by mapping speaker numbers to the names in the episode intro. Writes proposals to `pipeline/korjausehdotukset.json` (`uusi_suosittelija` may be `"tuntematon"`; saved incrementally after each episode, dedup by `(jakso_id, r_idx)` so reruns only process new flags). Nothing touches `suositukset.json` until proposals are reviewed and exported with `--vie` into `korjaukset.json`, then applied via `paivita_korjaukset.sh`. Proposals where the AI *confirms* the current name are candidates for `ohitukset.json` instead.

### Key invariants

- **`historia_json.txt` is the dedup oracle.** Each RSS `entry.id` is appended after a successful run. An episode that produces zero recommendations is still recorded (empty array stored) so it isn't reprocessed.
- **`suositukset.json` is ordered newest-first.** The main script iterates `reversed(feed.entries)` and prepends (`insert(0, …)`). `prosessoi_vanhat_jaksot.py` appends then re-sorts by parsed `paivamaara` (Finnish `%d.%m.%Y`). Don't break this ordering — the site depends on it.
- **Recommendation index `r_idx` is the position inside `jakso["suositukset"]`.** Corrections and skips reference it directly, so reordering or filtering recommendations within an episode will silently corrupt every existing `(jakso_id, r_idx)` reference. **Reordering recs within an episode** (to match the order they're mentioned) is the admin UI's "⇅ Muuta järjestystä" (Kaikki/Korjatut views, since 27.9.2026). It can't be a replayed correction entry — the whole korjaukset list is replayed by `r_idx` every run — so `netlify/functions/jarjesta.js` writes ONE commit via the Git Data API (blobs → tree → commit → `PATCH refs/heads/main` with `force:false`, retried up to 3× on 422 when main moved) that changes `suositukset.json` AND remaps every `r_idx` of that episode in `admin/korjaukset.json`, `admin/ohitukset.json` and `admin/epailyttavat.json`/`.js`. The pure logic is `netlify/lib/jarjestys.js` (`jarjestaJakso`), which validates the permutation, rejects stale browser data (the sent `teokset` must match main's recs → 409), and refuses while the episode has a saved-but-unapplied addition (its slot depends on the current length → 409); the UI also blocks while the episode has unsaved edits or new recs, and after success remaps its in-memory data (`sovellaJarjestysPaikallisesti`) so the ~1 min deploy lag doesn't confuse further edits. Output uses `JSON.stringify(x, null, 2)`, byte-identical to the Python writers' `json.dump(indent=2, ensure_ascii=False)` (verified). A commit that changes no korjaukset/ohitukset entry doesn't trigger the automation — fine, since the function already remapped the validation data. Verified 27.9.2026 with real data (every rec moved, 4 corrections remapped, `sovella_korjaukset.py` replay leaves data unchanged) and a mocked GitHub API incl. the 422 retry. Manual reorders by editing `suositukset.json` must follow the same rule (remap references, or only move slots nothing references).
- **The Claude prompt is load-bearing.** It enforces the JSON schema (`teos`, `paakategoria` from a closed list, `google_linkki`, `lisatieto_linkki`, `kuvaus`, `suosittelija`, `kategoriat`) and Finnish translation of foreign names. Changing it changes the output schema — touch with care. The prompt lives **only** in `scripts/uutisraportti_automaatio_deepgram_claude.py` (`rakenna_system_prompt`); `pipeline/prosessoi_vanhat_jaksot.py` and `pipeline/korjaa_suosittelijat.py` import from that module (via a `sys.path` insert). Since 16.9.2026 there is no second copy to keep in sync. Key prompt rules (each added after a real production failure): include joke/atypical recommendations; exclude self-promo ads, news topics, and the host's framing-scenario segues — with one narrow carve-out (27.9.2026, user decision): a speaker's tip in the rec section to listen to a specific *other outlet's* episode where they were a guest (e.g. Tuomas on Futucast / Luomakunta, 3.9.2026) IS a rec, while talking about one's own series is not; a broader "when in doubt, include" wording was tried and rejected because it resurrected the Aperol Spritz framing prop (20.8.), an own-series mention and a news-topic "rec"; fix transcription errors in titles only when certain, otherwise keep as heard and set `epavarma_teos: true` (never substitute a different known work by the same artist); require a `puhuja_peruste` evidence quote for every speaker→name mapping, else `"tuntematon"`; **speaker-evidence hierarchy** (added 27.9.2026 after the 24.9.2026 episode swapped Marko and Salla): Deepgram's diarization boundaries often slip a word or two at turn changes, so a vocative at the start/end of a turn ("Marko? Eikö se…" — actually Tuomas handing over, landed on Marko's line) and end-of-episode thank-yous are WEAK evidence, while self-introductions and third-person references ("Salla puhuu siitä…" → speaker isn't Salla) are STRONG; the model must gather all clues before deciding and report conflicts in `puhuja_ristiriita` (→ email warning). **Ads rule** (27.9.2026): the podcast host inserts *current* ads into the audio at download time, so even years-old episodes re-transcribed now start with e.g. HS's "Menetetyt miljardit" trailer (Tuomas + an archive clip of Fortum's CEO, found in 34 transcripts) — the prompt says ad/trailer voices are not participants, ad content is not a rec, and the episode proper starts at the host's welcome. The prompt's examples deliberately use a made-up name ("Anna"), not this episode's. `puhuja_peruste`, `puhuja_ristiriita` and `epavarma_teos` are internal QA fields (`SISAISET_KENTAT`) — they feed the warnings and the email's `tunnistukset` list, then get stripped before saving, so the site schema is unchanged. `analysoi_claudella` returns a 3-tuple `(suositukset, varoitukset, tunnistukset)`. Known limitation: validators only catch misspelled/non-participant names, never a swap between two valid participants — the email's evidence list is the safeguard.
- **Recommender attribution is per-episode, not a fixed whitelist.** The main script parses the episode's participants from the RSS description (via `poimi_osallistujat_rss`, imported from `validoi_suosittelijat.py`) and injects them into the prompt as the only allowed `suosittelija` values; the RSS description is also passed as context in the user message. The model must cite a `puhuja_peruste` evidence quote for each mapping or output `"tuntematon"` — the validator flags those for manual review. **The name spelling never stays model-authored**: `normalisoi_suosittelija` snaps the output to the participant list (exact / ≥0.85 similarity / first- or last-name match), and an unmatched name becomes `"tuntematon"`. When the RSS description names no participants (happens regularly), only near-miss spelling is normalized against `TUNNETUT_NIMET` and unknown names survive (could be genuine guests). Note the main script's system prompt is an f-string: literal `{`/`}` in the JSON example must stay escaped as `{{`/`}}`.

Anni Keski-Heikkilä was a podcast regular but left HS (~2023) and won't appear in new episodes; a bare "Anni" in old RSS descriptions means her, not Anni Lassila. - **Participant parser (`poimi_osallistujat_rss` → `poimi_osallistujat_tiukasti`, strict since 27.9.2026).** Names come only from the part *before* a participant verb ("Tuomas, Marko ja Salla keskustelevat …"; verbs in `OSALLISTUJAVERBIT`, every such sentence is read), the "… kanssa" part (inflected names allowed: "Hanna Mahlamäen kanssa"; unknown guests there are ignored), and known full names in guest sentences (`VIERAILU`: vierailee/saapuu/kertoo …). Sentences split only on `[.!?]`+space ("HS:n", "P. Orpon" don't cut); word boundaries so "Marko Junkkarin hiihtolomaillessa" isn't a participant; a first name followed by a different surname is a guest, not the mapped regular ("Hanna Mahlamäki" ≠ Hanna Havusto, "Teemu Luukan kirja" ≠ Teemu Muhonen), while a shorter near-surname is a typo ("Maria Manne" → Maria Manner). **Name lists without a listed verb** (`_nimiluettelot`, added 1.10.2026 after 27.3.2025 "Salla, Marko ja HS:n … Inkeri Harju äimistelevät" returned only Inkeri and 11.4.2024 "Studiossa Tuomas Peltomäki, Jari Hanska ja Salla Vuorikoski." lost Jari Hanska): a list after a strong marker ("Studiossa (ovat)", "(Podissa) mukana (ovat)") up to sentence end; after a weak marker ("Tämän viikon podcastissa/jaksossa", or after an `OSALLISTUJAVERBIT` verb: "keskustelevat Sohvi, Marko ja …") only if it ends in a plural verb (-vat/-vät) or at sentence end; at sentence start only with ≥2 names + plural verb. Titles/short descriptions before a name are skipped ("HS:n audio- ja sometoimittaja", "vieraileva tähti", "politiikan toimittaja", "puhelinyhteydellä Washingtonista"), quoted nicknames removed, "Timo R. Stewart" doesn't split the sentence. **Unknown full names are returned as-is** (guests: Jari Hanska, Teija Sutinen …) — `normalisoi_suosittelija` then keeps the guest's spelling, and the validators flag such recs because they aren't in `TUNNETUT_NIMET` (same as the older "Jussi Sippola" verb-subject case). A bare first name resolves via `ETUNIMI_KARTTA` (now also joona/heini/oskari for the 2023–24 summer teams, "AKH" = Anni Keski-Heikkilä) or, if exactly one `TUNNETUT_NIMET` entry has that first name, to it ("vieraileva tähti Jukka" → Jukka Huusko, "Emil" → Emil Elo, both checked against the data); otherwise it's dropped. A same-surname first-name typo snaps to the known name ("Susanne Reinboth" → Susanna Reinboth). Inflected guests are read in sentences with vieraakseen/vieraaksi/studioon/kanssa (`_taivutetut_vieraat`: "Tuomas Niskakankaan", "Anna-Sofia Bernerin", "Tuijan kanssa" → the only Tuija). Old vs new compared on all 451 RSS entries: 47 differ, all reviewed as fixes (fallback use fell from 184 to 64 entries). Only when this finds no names does it fall back to the old broad parser (`poimi_osallistujat_laajasti`: full-name scan of the whole description + first names around "Studiossa"/"keskustelevat"). The old parser used to read the topic text after the verb, putting absent or unrelated people into production's allowed-recommender list ("ilman Tuomas Peltomäkeä" → Tuomas). Compared on all 450 RSS entries before switching: 37 differ, all reviewed as fixes.
- **Model fallback list (`MALLIT`).** Extraction tries `claude-sonnet-5` → `claude-sonnet-4-6` → `claude-haiku-4-5-20251001` → `claude-opus-4-6`. Two API constraints baked into `kysy_claudelta`: **no `temperature` parameter** (Sonnet 5 rejects it with a 400, which would silently drop every call to the fallback model — and worse, the current anthropic SDK doesn't accept the kwarg at all, raising `TypeError` for *every* model: this silently broke `scripts/generoi_muutosloki.py` from 15.8. to 15.9.2026, fixed by dropping the param) and text extraction must filter `response.content` by `block.type == "text"` (newer models can emit thinking blocks first). A JSON parse failure also advances to the next model instead of being treated as an empty result. **Streaming + `max_tokens=32000`** (since 27.9.2026): Sonnet 5 thinks adaptively by default and thinking consumes `max_tokens` — the old non-streaming 8000 cap regularly produced a thinking-only response (`stop_reason: max_tokens`, no text), silently falling back to weaker models (seen 2/3 test runs even on the old prompt); a large cap needs `client.messages.stream(...).get_final_message()` to avoid HTTP timeouts. Sonnet 4.6 sometimes writes its reasoning before the JSON, so parsing falls back to the outermost `[...]` in the text.
- **Validator exact-spelling invariant.** Both `pipeline/validoi_suosittelijat.py` and `scripts/generoi_validointidata.py` flag any `suosittelija` that is not exactly in `TUNNETUT_NIMET` (except `"tuntematon"`), even when the loose first/last-name match passes — a near-miss like "Johnn Helin" previously slipped through on the surname match.
